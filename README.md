# G.Scacco

A personal blog about programming and computer science, built as a static site with [Hugo](https://gohugo.io/).

The theme lives directly in the repository, in the `layouts/` templates and the `static/css/site.css` stylesheet, so no external themes or dependencies are required. Typography is self-hosted, and the Nix flake provides a consistent Hugo version without requiring a system-wide installation.

## Requirements

Choose one of two setup options:

- **Nix** (recommended): all you need is Nix with flake support. Hugo is provided by the development shell.
- **Local Hugo**: `hugo` must be installed and available on your `PATH`.

## Local development

With Nix, enter the development shell and start the server:

```sh
nix develop
hugo server --buildDrafts --port 8080
```

Alternatively, use a single command:

```sh
nix develop --command hugo server --buildDrafts --port 8080
```

The site will be available at <http://localhost:8080/>. Hugo automatically reloads changes to content, templates, and styles.

If Hugo is already installed, run it directly:

```sh
hugo server --buildDrafts --port 8080
```

`--buildDrafts` also includes articles with `draft = true`. To include only published content, omit this option.

## Building the site

To create the static version in the `public/` directory:

```sh
hugo
```

With Nix, the reproducible build is created under `result/`:

```sh
nix build
```

Before publishing, validate the flake with:

```sh
nix flake check
```

## Writing a new article

Create a new content item from the project archetype, placing it in the relevant editorial group:

```sh
hugo new content/post/<group>/title.md
```

The groups are `spreadsheet/`, `cronx/`, `clojure/`, and `tools/`. The file is created with `draft = true`. Complete the front matter, write the content in Markdown, and set `draft = false` when the article is ready to publish.

To link one article to another, use Hugo's `relref` shortcode instead of a relative path:

```go-html-template
[See also]({{< relref "/post/<group>/another-article.md" >}})
```

This lets Hugo generate the correct link even when permalink URLs change.

### Editorial front matter

The archetype includes several optional fields:

```toml
description = "A concise summary used on the homepage, in search results, and in social metadata."
subtitle = "An optional standfirst shown below the article title."
featured = false
featured_rank = 1
topics = ["programming-languages"]
series = ["example-series"]
showToc = false
```

- `featured = true` selects an article for the homepage. `featured_rank` orders selected articles: the lowest rank becomes the lead essay. If no article is marked, the most recent one is used.
- `topics` assigns the article to broad areas of exploration. The homepage currently uses `programming-languages`, `software-architecture`, `programmable-environments`, and `systems-design`.
- `series` groups articles into ordered sequences. The homepage currently presents `programmable-spreadsheet` and `cronx`; `project-euler` is also modeled as a series.
- `showToc = true` forces the table of contents; by default it is shown for articles longer than 700 words.
- `description` is also used in previews instead of the summary generated by Hugo.

The homepage's exploration areas and series descriptions live in `data/homepage.yaml`. Topics and series are regular Hugo taxonomies, so their term pages are generated at `/topics/<term>/` and `/series/<term>/` without changing article URLs.

## Editorial components

The components are Hugo shortcodes and work directly in Markdown. The main examples are:

```go-html-template
{{< callout type="note" title="A useful distinction" >}}
Markdown content for the callout.
{{< /callout >}}

{{< pullquote cite="A Reader" >}}
A sentence worth pausing on.
{{< /pullquote >}}

{{< figure src="/images/example.svg" alt="Description" caption="A caption." number="1" >}}

{{< diagram name="edn-views" caption="Description" number="2" wide="true" >}}

{{< terminal title="shell" >}}
$ hugo server --port 8080
{{< /terminal >}}

{{< details summary="Open the details" >}}
Additional explanation or an optional visualisation.
{{< /details >}}

{{< sidenote >}}
A marginal note shown beside the article on wide screens.
{{< /sidenote >}}

{{< split ratio="7-5" >}}
{{< split-col >}}
Markdown for the first column.
{{< /split-col >}}
{{< split-col >}}
Markdown or an image for the second column.
{{< /split-col >}}
{{< /split >}}
```

Diagrams should be stored in `assets/diagrams/` as SVG files with `<title>` and `<desc>` for accessibility. Standard Markdown images automatically receive a figure and caption when a title is present:

```markdown
![Alternative text](/images/example.svg "Optional caption")
```

## Design and assets

- Palette: paper `#F4F1E9`, ink `#24251F`, accent `#A45C36`, secondary text `#6B6A63`.
- Self-hosted fonts in `static/fonts/`: Newsreader for headings, IBM Plex Sans for body text, IBM Plex Mono for code and annotations.
- Original illustrations in `assets/diagrams/`; no additional JavaScript and no CSS frameworks.

## Projects

The `/projects/` page and the homepage section read from `data/projects.yaml`. Each entry has `name`, `kicker`, `description`, `url`, and `status`. The page is defined in `content/projects/_index.md` and uses `layouts/projects/list.html`.

## Project structure

- `content/post/spreadsheet/`: articles on spreadsheets as programmable environments.
- `content/post/cronx/`: the cronx design and observability series.
- `content/post/clojure/`: Project Euler and other Clojure programming articles.
- `content/post/tools/`: software tooling articles.
- `content/projects/`: project index page.
- `data/projects.yaml`: data shown on the projects page and homepage.
- `assets/diagrams/`: SVG diagrams processed by Hugo.
- `layouts/`: theme templates and partials.
- `layouts/shortcodes/`: editorial components usable in Markdown.
- `static/`: CSS, favicon, and fonts served without processing.
- `archetypes/`: template used by `hugo new`.
- `config.toml`: site configuration, menus, permalinks, and parameters.
- `flake.nix`: Nix development and build environment.
- `.github/workflows/hugo.yml`: automated build and deployment to GitHub Pages.

## Publishing

The GitHub Actions workflow publishes the site to GitHub Pages on every push to the `master` branch. CI uses Hugo `0.168.0`, the same version provided by the flake, and uploads the `public/` directory as the Pages artifact.
